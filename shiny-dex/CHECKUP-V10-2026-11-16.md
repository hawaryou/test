# Rapport d'audit — ShinyDex Hawaryou v10.1
Date : 16 novembre 2026.
Source : https://github.com/hawaryou/test/tree/main/shiny-dex
Application : https://hawaryou.github.io/test/shiny-dex/

## Portée et résultats
L'audit a porté sur 46 écrans et les ressources déclarées dans la PWA. Tous les écrans ont généré leur contenu sans exception JavaScript dans un environnement de test isolé avec les données historiques de la collection. Les états initiaux contenaient environ 1 297 actions visibles, dont 454 sur les 10 vues principales. Ce chiffre ne signifie PAS que 1 297 clics physiques ont été réalisés.
Les 46 écrans : dashboard, pokedex, captures, forms, hunts, analytics, goals, achievements, share, settings, boxes, regions, collectionplus, huntlab, insights, personalize, studio, restore, plus, gameguides, livingforms, consistency, expertstats, quests, museum, bingo, timeline, yearreview, sync, video, showroom, regionatlas, gamethemes, posters, searchhub, quickcapture, tutorial, dashboardlayout, multihunt, sessionjournal, huntstatistics, importreview, conflicts, syncdiagnostics, drivebackups, reminders.
Le Google Sheets réel a été consulté EN LECTURE SEULE : 285 captures SH-0001 à SH-0285. L'instantané de l'application contient 285 captures, 347 exemplaires et 124 997 tentatives. Les en-têtes Journal, Métadonnées, Chasses et Organisation correspondent au modèle Apps Script.

## Essais réussis avec données simulées
- Navigation des écrans principaux et des routes rapides de recherche et saisie.
- Formulaire de capture : rejet d'un compteur négatif, création valide et conservation des métadonnées avancées.
- Création d'une chasse, d'un objectif et d'un souhait en file locale.
- 40 modifications du même compteur hors ligne : valeur finale correcte, une seule écriture en attente après fusion.
- 120 modifications d'une même clé complémentaire hors ligne : valeur finale correcte, file fusionnée.
- Relecture Google Sheets simulée : une modification locale non confirmée d'une capture existante reste visible.
- Restauration avec file non vide : blocage explicite pour prévenir la perte de données.
- Import CSV avec une nouvelle capture, un doublon et une ligne invalide : une capture ajoutée, aucun ancien enregistrement remplacé.
- Tableau multi-chasse : fin de chasse confirmée, événement créé, formulaire de capture ouvert.
- Apps Script simulé : création et édition de capture, métadonnées, données complémentaires, compteur de chasse et conflit de révision.
- Test de capacité serveur : écriture correcte en lignes 2501 puis 2502 ; pas de réutilisation de la ligne 2501.
- Références du cache PWA : les 33 ressources de l'accueil sont répertoriées dans le cache.

## Problèmes corrigés dans GitHub
1. Des boutons pointant vers une page avancée étaient sans effet : le routeur reconnaît désormais la destination, et les actions inconnues sont signalées.
2. Les compteurs normaux, multi-chasse, widget et vidéo ne créaient pas immédiatement d'opération en attente : désormais sauvegarde locale durable à chaque appui, avec fusion des écritures successives.
3. Fusion des modifications répétées de données complémentaires hors connexion.
4. Une actualisation serveur pouvait masquer une modification locale en attente : fusion prioritaire de cette modification.
5. La restauration pouvait supprimer des opérations non transmises : blocage avant restauration et message explicite.
6. L'ancien import brut contournait l'assistant sécurisé : redirection vers la vérification des doublons.
7. Notifications indisponibles : rappel visible dans l'application si les notifications système sont refusées ou incompatibles.
8. Le bouton Capture du tableau multi-chasse ne terminait pas la chasse : fin et ouverture du formulaire après confirmation.
9. Galerie de favoris vide difficile à fermer sur téléphone : bouton de fermeture et désactivation de l'ouverture si vide.
10. Export JSON historique incomplet : conservation des données avancées.
11. Partage par presse-papiers : alternative manuelle si refusé.
12. Mise en cache limitée de 180 sprites publics déjà consultés pour l'usage hors ligne.
13. Apps Script : suppression de la réutilisation de la ligne 2501 et de la lecture tronquée après 2500/3000 lignes.

## Limites de validation
Le site GitHub Pages n'était pas accessible directement depuis l'environnement de test. Les 46 vues ont été évaluées par exécution du code, mais chaque bouton n'a PAS été touché sur un véritable iPhone. Le rendu visuel et les permissions Safari, caméra, plein écran, Wake Lock, impression PDF et notifications ne sont donc pas attestés en production.
La synchronisation réelle nécessite encore l'installation et le redéploiement du ShinyDexAPI.gs par le propriétaire du projet, sans supprimer l'ancien Code.gs. Les fonctions doGet/doPost existantes du projet doivent être examinées pour éviter les conflits de noms.
Les sauvegardes Drive ne sont pas activées avant l'exécution volontaire du déclencheur dans Apps Script. Aucun Web Push en arrière-plan n'est configuré. La gestion des conflits entre deux appareils reste partielle pour les types de données autres que les chasses.

## Contrôle de réception conseillé
iPhone : actualiser en connexion, explorer les menus, vérifier la recherche, la galerie, les formulaires, un compteur avec mode avion puis reconnexion, le rangement HOME, les dialogues de confirmation et la file d'envoi.
Ordinateur : vérifier toutes les tailles d'écran, les formulaires longs, l'import avec doublons, les exports PDF, les raccourcis clavier et les impressions.
Apps Script : installer le dernier fichier serveur, redéployer, exécuter les diagnostics, vérifier une écriture de test volontaire et la confirmation de son statut sans modifier les captures historiques.

Ce rapport distingue les tests simulés des vérifications en production restant à faire.
